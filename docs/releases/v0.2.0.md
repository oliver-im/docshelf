# DocShelf Web 0.2.0

Keep frequently used documents in a **Pinned** section above the project list. Open a document's actions menu, or right-click its row, and choose **Pin document**. Each shortcut shows its project and folder, while the original row retains a pin indicator. **Unpin document** works from either location.

Pins are saved per shelf in this browser, survive reloads and title or route changes, and update across tabs at the same site. Temporarily absent documents regain their shortcut when they return. Browser-imported public documents can also be pinned. DocShelf Web and Obsidian keep separate pin lists.

## Other changes since 0.1.0

- Browse documents in nested folder trees and remove a project or folder through a reviewed shelf action without changing its source files.
- New documents and agent-announced updates show unread indicators. Opening a document or choosing **Mark all as read** clears the relevant indicators.
- Browser scripts now have stricter type checks and safer DOM and response handling. Mermaid output is sanitized before rendering.
- The repository now stages the independently versioned Obsidian plugin for community build verification and documents the distinction between the two apps' review findings.

## Install or update

Use Node.js 24 or newer and a filesystem with symbolic-link support. Follow the [installation instructions](https://github.com/oliver-im/docshelf/blob/v0.2.0/README.md#get-started) or the [existing-installation upgrade guide](https://github.com/oliver-im/docshelf/blob/v0.2.0/docs/local-server.md#updating-an-existing-installation). Preserve `shelf.local.json`, the configured workspace root, and your existing local address. Restart the watcher after updating and installing dependencies with `npm ci`.

Existing shelf versions, document routes, source-line links, and browser imports stay compatible. No migration is required for pins. The Obsidian plugin is released separately with plain `X.Y.Z` tags; this web release does not replace its install assets.

## Verification and limits

Verification includes aggregate tests, static checks, builds, and browser checks for keyboard actions, nested folder context, pin navigation, reload persistence, tab synchronization, shelf isolation, focus restoration, and touch controls. Local verification uses macOS and Brave; CI covers Ubuntu. Windows and a broad browser matrix remain unverified.

Browser imports remain limited to public GitHub Markdown and published Claude Artifacts. Full-text search covers registered local documents. Local additions, removals, and live rebuilding require the loopback watcher. Pins are browser-local preferences and do not modify the shared shelf or original documents.
